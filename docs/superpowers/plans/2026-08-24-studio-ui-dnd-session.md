# Studio UI, Drag-and-drop and Session Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make the Studio immediately cloud-aware, eliminate automatic copy chains, support direct asset drag-and-drop, and clean up the most visible button layout problems.

**Architecture:** Keep placement and reconciliation rules in testable JavaScript modules, while Svelte components only translate browser events and render state. Restore the publisher session before cloud bootstrap, then reuse the existing revision/conflict pipeline and its `updatedBy` metadata.

**Tech Stack:** Svelte 5, browser Drag and Drop API, Node test runner, Playwright, Cloudflare Worker

**Spec:** `docs/superpowers/specs/2026-08-24-studio-ui-dnd-session-design.md`

## Global Constraints

- Publisher sessions last exactly seven days on the current browser.
- OAuth state remains short-lived.
- No new runtime or UI dependency.
- Touch placement remains available.
- Automatically generated local backups never become publish candidates.
- Verification is targeted Node tests, one focused Playwright flow, and the Studio build.
